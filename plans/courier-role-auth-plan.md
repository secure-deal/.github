# Courier role and auth plan

## Цель

Добавить `courier` как полноценную роль в монорепозиторий Easy Grocery и модель backend-аутентификации.

## Область изменений

- `app/courier-frontend` — выделенный Telegram Web App для курьеров.
- `app/backend/src/modules/courier` — выделенная backend-поверхность для кода, связанного с курьерами.
- Общая инфраструктура ролей/аутентификации в backend должна распознавать `courier` ещё до появления таблицы courier.

## Планируемые изменения

1. Обновить репозиторные инструкции так, чтобы courier был явно включён в структуру монорепозитория и границы backend-модулей.
2. Обновить backend-инструкции, чтобы courier-код оставался внутри `src/modules/courier`.
3. Расширить общие role-типы аутентификации, добавив `courier`.
4. Добавить имена auth-cookie с учётом courier и экспорты для courier auth-хелперов.
5. Обновить обработку JWT/сессий так, чтобы courier обрабатывался как отдельная роль и не проваливался в admin/operator-логику.
6. Сохранить безопасные проверки активации courier до появления слоя персистентности courier.
7. Добавить в модель courier геолокацию: `lat` и `lon` (долгота), с валидацией диапазонов координат.
8. Добавить кэширование актуальной позиции courier для быстрых чтений (последняя точка + время обновления).
9. Добавить обработку обновления позиции при движении courier с сохранением местоположения в хранилище.

## Геолокация и кэширование courier

- В модель courier добавить координаты `lat` и `lon` как обязательные поля текущей позиции после активации геотрекинга.
- При каждом событии перемещения обновлять текущую позицию courier и сохранять её в персистентном хранилище.
- Последнюю позицию courier хранить в кэше для быстрых запросов трекинга; при промахе кэша читать из основной БД и прогревать кэш.
- Для записи в кэш хранить минимум: courier_id, lat, lon, updated_at.
- На старте реализации определить политику истории перемещений: хранить только последнюю точку или журнал координат за период.

## Примечания

- Не добавлять таблицу courier на этом этапе.
- Не смешивать courier-бизнес-логику с деревьями модулей `client` или `merchant`.
- Сохранить текущее поведение admin, operator, merchant и client.
- Для геолокации использовать единые названия полей `lat` и `lon` (не `lan`).
